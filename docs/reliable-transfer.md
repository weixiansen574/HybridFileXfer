# 4.0 可靠传输与桌面客户端说明

本文档介绍 `4.0.1-preview`（协议版本 **401**）的新增特性、使用方法与编译流程。由于传输协议与握手机制升级，**Android 手机端与电脑端必须同时使用 4.0（协议 401）版本**，无法与 3.0 旧版或协议 400 混用。

---

## 一、连接与配对流程

1. **打开电脑端**：运行桌面图形界面（或使用命令行模式），选择 **USB 设备（ADB）** 或 **手机网络地址（Wi-Fi / 局域网）**，设置电脑端接收目录并点击 **『开始连接』**。
2. **USB (ADB) 连接**：需电脑已安装 Android `platform-tools`（`adb`）且手机已开启并授权 USB 调试。勾选“连接时打开手机 App”可由电脑直接唤起手机端应用；配对码留空时，电脑端会通过已授权的 ADB 通道自动获取手机当前会话的配对码与监听端口。
3. **局域网直连**：手机端启动服务后会显示当前会话的配对码与端口（默认 `5740`），将其填入电脑端即可建立连接。
4. **选择文件与发起传输**：连接建立后，在手机端的双栏文件浏览器中选择文件，点击底部的 **『手机 → 对端』** 或 **『手机 ← 对端』** 按钮开始传输。电脑端窗口实时显示总体进度、各网卡通道速率、传输历史与诊断日志。
5. **断线重连与断点续传**：连接意外断开后可在同一窗口直接重连。重连后在手机上重新选择同一批源文件和目标目录，程序会自动校验已保存的临时文件前缀并从断点处继续传输。

> **权限说明**：配对连接后，手机端双栏文件管理器可访问电脑当前登录用户权限范围内的路径，请仅与受信任的设备配对。手机端可选用正常模式、Root（直接 su）模式或 Shizuku（ROOT / ADB）模式，具体可访问的目录（如外置存储、`Android/data`、`/data`）取决于所选模式及系统权限。

## 二、文件保护、断点续传与数据校验

1. **临时暂存与原子提交**
   - 接收文件时，数据会先写入目标目录下的 `.hfx-*.part` 临时暂存文件，待完整接收并通过校验后，再按设定的同名文件策略（**保留两份**、**跳过**或**覆盖**）提交为正式文件。
   - 若传输中途断线或取消，原有的源文件与目标目录中已有的同名文件均不会被破坏；单个文件因无权限、文件名不合法或读写错误失败时，会记录具体原因并继续传输其余文件。

2. **断点续传与内容增量跳过**
   - **断点续传（默认开启）**：中断的暂存文件会保留已确认写入的数据前缀与 `.meta` 元数据；下次续传前会先核对已保存前缀与源文件是否一致，一致则直接接着传剩余部分。
   - **内容增量跳过（可选开启）**：遇到同名文件时，通过比对源文件与目标文件的完整内容哈希决定是否跳过，避免仅凭文件大小相同而误判。

3. **CRC32 分块校验与可选 SHA-256 全文件校验**
   - **CRC32 分块校验（始终开启）**：发送端在内存缓冲区直接计算每个数据块的 CRC32，接收端核对通过后才落盘并回复确认帧；若分块校验不匹配则自动重传该块，若某条网卡通道持续出错则自动将该通道未确认的分块转交其余健康通道继续传输。
   - **传输后完整 SHA-256 校验（默认关闭，任一端开启即生效）**：所有文件数据接收完毕后，手机与电脑两端并发计算文件 SHA-256 摘要并比对；每轮比对结束后自动批量重传摘要不一致的文件并再次校验。
   - **停止校验与重试**：在 SHA-256 校验阶段，用户可随时点击 **『停止校验与重试』**。此时连接不会断开，已完成接收但尚未走完 SHA-256 比对的文件也会安全保留（若目标位置已有同名旧文件，会另存副本以保护原文件）。协议内部细节见 [校验协议技术说明](verification-protocol.md)。

## 三、从源码构建

### 1. 构建电脑端（Windows / Linux / macOS）

需要 **JDK 21**（或更高版本）与 **Python 3.9**（或更高版本）：

```bash
python tools/build_desktop.py --test --package
```

- 首次构建会从 Maven Central 下载固定版本的 FlatLaf 3.7.2 并校验 SHA-256，随后缓存于 `.tools/dependencies`。
- 产物输出在 `.build/distributions`：
  - `HybridFileXfer.jar`：包含界面的单文件 JAR（字节码兼容 Java 8），可通过 `java -jar HybridFileXfer.jar` 启动。
  - `HybridFileXfer-4.0.1-<系统>-<架构>.zip`：包含当前平台 Java 运行时的免安装桌面压缩包，Windows 下解压即可运行 `HybridFileXfer.exe`。
- 构建脚本会将当前 Git 提交号、工作区状态及源码仓库地址写入 `SOURCE.txt`（默认指向 `weixiansen574/HybridFileXfer`，在复刻仓库构建时可通过 `--source-repository OWNER/REPOSITORY` 指定），并自动将 GPL-3.0 许可证、[CHANGES.md](../CHANGES.md) 与 [THIRD_PARTY_NOTICES.txt](../THIRD_PARTY_NOTICES.txt) 打包进分发产物。

### 2. 构建 Android 手机端

需要 **JDK 17**、**Android SDK 34** 及项目配置的 NDK / CMake。进入 `HybridFileXfer-Android` 目录执行：

```bash
./gradlew --no-daemon assembleDebug testDebugUnitTest lintDebug
```

Windows 下请使用 `gradlew.bat`。构建时会自动将根目录下的许可证、修改说明与第三方开源声明同步到 APK 的 `assets/licenses` 目录中。若手机上已安装不同签名的旧版应用，请先卸载旧版再安装新编译的 APK。
