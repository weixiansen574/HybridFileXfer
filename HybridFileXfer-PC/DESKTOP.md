# 桌面客户端使用说明

4.0 版本的电脑端同时提供**图形界面（GUI）**与**命令行（CLI）**两种运行方式：

- **便携版发行包**：自带 Java 运行环境，Windows 下解压后直接运行 `HybridFileXfer.exe`（macOS / Linux 运行对应可执行文件）即可打开图形窗口，不会弹出额外的黑框命令行窗口。
- **独立 JAR 包**：若已安装 Java 8 及以上运行环境，可直接执行 `java -jar HybridFileXfer.jar` 启动图形界面。

界面采用 FlatLaf 跨平台外观，右上角支持切换**跟随系统**、**浅色**或**深色**主题，切换外观时不会中断当前连接或传输任务。

---

## 一、连接手机

电脑端支持先打开窗口并等待手机上线。连接步骤如下：

1. **选择连接方式与电脑目录**
   - 在电脑窗口选择 **USB 设备**（通过 ADB 转发）或 **手机网络地址**（通过 Wi-Fi / 局域网直连），并设置电脑端的默认接收文件夹。
   - 勾选 **『自动等待与重连』** 后，点击 **『开始连接』**，电脑端会持续等待手机准备就绪。

2. **USB (ADB) 连接**
   - 需要手机在开发者选项中开启“USB 调试”，并在首次连接电脑时点击“允许 USB 调试”。
   - **自动配对**：在 USB 模式下，配对码输入框留空即可。只要手机端已启动服务，电脑端会自动通过 ADB 读取当前会话的配对码与端口。
   - **从电脑唤醒手机端**：勾选 **『连接时打开手机 App』**（或点击 **『打开手机 App』**）后，电脑会直接唤起手机端应用并弹出配对确认框，在手机上点击确认即可完成连接。

3. **无线局域网（Wi-Fi / 热点）连接**
   - 确保手机与电脑处于同一局域网（或一方连接另一方的热点）。
   - 在手机端启动服务后，将手机界面上显示的**服务地址（IP）**、**端口**和**配对码**填入电脑窗口，点击 **『开始连接』** 即可。

> **安全提示**：连接成功后，手机端双栏文件管理器可以浏览并操作当前电脑系统账户有权限访问的目录。请仅在受信任的个人设备之间配对连接。

## 二、文件传输与状态查看

- **发起传输**：连接建立后，文件选择仍在**手机端的双栏文件管理器**中进行。电脑端窗口负责实时展示当前传输进度、各网卡通道的上传/下载速率、传输结果汇总以及历史记录。
- **断线重连與续传**：如果中途断开连接，可直接在当前电脑窗口重新连接；重连后在手机上再次选择同一批文件和目标文件夹，程序会自动核对已写入的部分并从断点处继续传输。
- **传输历史与诊断日志**：
  - **传输历史**：可选择在本机保留最近 100 条传输摘要（保存在 `~/.hybridfilexfer/history.tsv`）。
  - **诊断日志**：记录当前会话的连接与传输状态，支持直接复制或点击 **『保存日志』** 导出为 UTF-8 文本文件，方便排查网络或权限问题。

## 三、高级设置（文件保护、校验与端口）

点击电脑窗口中的 **『高级设置』** 可调整以下选项：

1. **同名文件处理**
   - **保留两份（默认）**：自动为新文件附加序号后缀，不覆盖原有文件。
   - **保留已有文件（跳过）**：遇到同名文件直接跳过。
   - **覆盖**：传输并校验完成后替换原有文件。
   - **内容一致时跳过（增量传输）**：传输前比对源文件与目标文件的完整内容，内容完全相同时自动跳过（不会仅凭文件大小相同就跳过）。

2. **分块校验与可选 SHA-256 全文件校验**
   - **CRC32 分块校验（始终开启）**：每个数据块在传输时都会校验 CRC32，发现传输错误立即重传该分块，几乎不增加额外耗时。
   - **传输后完整 SHA-256 校验（默认关闭，可选开启）**：在手机或电脑任意一端勾选即可生效。所有文件数据传输完成后，两端会同时计算文件 SHA-256 摘要并逐一比对；若发现摘要不一致会自动批量重传并再次校验。
   - **停止校验与重试**：如果文件较大、不想继续等待 SHA-256 校验，可在校验阶段随时点击 **『停止校验与重试』**。此时已完整接收的文件会直接保留（不会断开连接），而数据传输阶段的 **『取消传输』** 则会立即中止当前传输。

3. **端口与 ADB 选项**
   - **手机服务端口**：默认 `5740`，若手机端修改了监听端口，请保持两端一致。
   - **ADB 本地端口**：默认 `0`（由系统自动分配空闲本地端口，可避免 Windows 保留端口冲突）。程序断开时只会清理自身创建的转发规则。
   - **ADB Burst Mode（实验项）**：仅对本程序调用的 ADB 子进程启用 `ADB_BURST_MODE=1`，不会重启或干扰系统全局 ADB 服务。

## 四、命令行模式（CLI）

在启动命令中传入 `-c`、`-s`、`-d` 或 `--cli` 时会以命令行模式运行，适合脚本调用或无图形界面环境。执行 `--help` 可查看完整参数说明：

```text
java -jar HybridFileXfer.jar -c adb --launch-phone --wait
java -jar HybridFileXfer.jar -c adb -s DEVICE_ID -d "D:\Transfers" --pairing-code-file code.txt
java -jar HybridFileXfer.jar -c 192.168.1.2 --port 5740 --pairing-code-file code.txt
```

- `--wait`：当手机尚未就绪时自动重试（退避间隔上限为 15 秒），按 `Ctrl+C` 可随时停止。
- 在 ADB 模式下，若未指定 `--pairing-code` 或 `--pairing-code-file`，程序会自动读取手机端当前已启动会话的配对码。
- 当遇到配对码错误或两端协议版本不一致时，程序会立即停止重试并提示原因。

## 五、从源码构建与测试

需要安装 JDK 21（或更高版本）与 Python 3.9（或更高版本）：

```bash
python tools/build_desktop.py --test --package
```

- 首次构建会自动从 Maven Central 下载 FlatLaf 3.7.2 并校验 SHA-256，之后缓存在 `.tools/dependencies` 目录（若使用 IntelliJ IDEA 打开桌面模块，请先执行一次该脚本以准备依赖库）。
- 构建产物位于 `.build/distributions`，包含兼容 Java 8 字节码的独立 `HybridFileXfer.jar` 以及附带当前平台 Java 运行时的便携版压缩包。
- 若在其他 GitHub 仓库构建并分发产物，可通过 `--source-repository OWNER/REPOSITORY` 指定对应的源码仓库地址。
